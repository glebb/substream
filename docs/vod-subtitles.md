# VOD subtitles

Automatic is the default subtitle source. The player first tries a high-confidence OpenSubtitles match in the preferred language (Finnish or English), then a playable full embedded track in that language. Language preference takes priority over source: preferred-language embedded captions come before fallback-language OpenSubtitles. The other supported language follows the same order. Forced-only tracks are available manually; full ordinary tracks are preferred over hearing-impaired variants. There is one active subtitle source at a time.

Playback does not wait for subtitle search. Selection begins when the player is ready, with bounded embedded discovery and external search/activation. External search and activation each have a 20-second allowance, covering sequential series lookup/search and download/file requests on slower TVs. Explicit selection or Off invalidates pending automatic work. Late results cannot replace that choice. Re-selecting Automatic starts a new selection attempt. Manual choices are remembered on the device for that media source and title; embedded choices use language, label, variant metadata and an occurrence ordinal rather than a transient player index. A missing or unsupported saved selection falls back to Automatic without deleting the saved preference. Timing offsets are stored separately for each source/track; the subtitle menu disables adjustments the active renderer does not support. Remote navigation skips disabled adjustments in both directions so subtitle source and OpenSubtitles search remain reachable.

The title detail screen separately labels languages included in the video and languages found through OpenSubtitles. Embedded discovery reads a bounded Matroska/WebM prefix directly from the provider and caches only track metadata under opaque source identifiers on the device. An incomplete, blocked, or failed check is unknown availability, never evidence that no subtitles exist. Series containers are not probed: availability belongs to the selected episode.

## Platform support

Tizen AVPlay exposes native text tracks after preparation. For VOD, the app also supplies the same cached file metadata used in title details. This fills missing native languages, labels, forced and hearing-impaired flags without changing the AVPlay selection IDs. Matching uses subtitle order only when both complete lists have the same length and every known native language/Matroska codec anchor agrees; mismatches remain unknown. Matroska TrackNumbers are never used as AVPlay indices. Automatic tries the preferred external source immediately; when embedded fallback is needed, it waits for this bounded metadata check while video playback continues. A failed probe preserves native tracks and external fallback. Validate the correspondence on physical TVs, since firmware track filtering or reordering can differ. VOD selects them and enables AVPlay's native subtitle plane by default. This avoids depending on silent-mode callback delivery and lets firmware handle embedded text and supported bitmap tracks. Native subtitles expose no app font-size control; remote navigation skips those disabled buttons. Off/toggle, resume, track switching and replacement by OpenSubtitles keep the native plane synchronized with the active source. External SRT captions still use the shared overlay with app size and timing controls. An explicitly configured overlay renderer retains text callback cleanup and playhead-based cue expiry, but shipped playback uses the native renderer. Native timing adjustment uses `setSubtitlePosition` only when firmware accepts it. Confirm caption display and timing on physical Tizen 3 and Tizen 6 TVs; synthetic SDK mocks cannot establish firmware behavior.

Tizen details discovery uses a direct binary XMLHttpRequest with a one-MiB Range request, a 12-second timeout, and size checks at headers, progress and completion. It does not require streaming Fetch support or exposed Content-Length to read a bounded response. Oversized/ignored range responses are aborted. Unsupported or failed checks are not cached, including old unsupported cache entries. Non-Matroska media, blocked requests and incomplete metadata remain unknown; the details view explains that native track discovery still runs when playback starts.

Browser playback selects text tracks exposed by the browser/player engine. The app's injected external WebVTT track is excluded from embedded discovery. A browser may decode MKV video while exposing none of its embedded subtitles. The metadata reader can still report their presence, but does not extract or render MKV cue data. In that case Automatic uses OpenSubtitles when configured. Full client-side MKV cue extraction remains a separate feasibility step: bounded indexed range access, provider CORS/range support, seek alignment and older-device performance must be established before adding it. No server extraction/proxy is introduced.

Metadata probes send provider credentials directly only to the provider. They do not use companion services, hosting, access services or subtitle relays. API credentials continue to go to their respective APIs. See [client credential policy](client-credential-policy.md).

## Verification

Synthetic tests cover Matroska metadata and bounds, direct credential destinations, failed/aborted probes, safe cache storage, language ranking, language-first source choice, failed selection, manual/Off locks, late downloads, native/external exclusivity, remembered choices, source-specific timing and title-detail unknown states. Browser and TV preview verification should exercise Automatic, another embedded track, Off, external replacement, resume and remote focus. Real provider movies are device acceptance examples, never automated fixtures.
