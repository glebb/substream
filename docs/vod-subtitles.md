# VOD subtitles

Automatic is the default subtitle source. The player first tries a high-confidence OpenSubtitles match in the preferred language (Finnish or English), then a playable full embedded track in that language. Language preference takes priority over source: preferred-language embedded captions come before fallback-language OpenSubtitles. The other supported language follows the same order. Forced-only tracks are available manually; full ordinary tracks are preferred over hearing-impaired variants. There is one active subtitle source at a time.

Playback does not wait for subtitle search. Selection begins when the player is ready, with bounded embedded discovery and external search/activation. Explicit selection or Off invalidates pending automatic work. Late results cannot replace that choice. Re-selecting Automatic starts a new selection attempt. Manual choices are remembered on the device for that media source and title; embedded choices use language, label, variant metadata and an occurrence ordinal rather than a transient player index. A missing or unsupported saved selection falls back to Automatic without deleting the saved preference. Timing offsets are stored separately for each source/track; the subtitle menu disables adjustments the active renderer does not support.

The title detail screen separately labels languages included in the video and languages found through OpenSubtitles. Embedded discovery reads a bounded Matroska/WebM prefix directly from the provider and caches only track metadata under opaque source identifiers on the device. An incomplete, blocked, or failed check is unknown availability, never evidence that no subtitles exist. Series containers are not probed: availability belongs to the selected episode.

## Platform support

Tizen AVPlay exposes native text tracks after preparation. For VOD, the app also supplies the same cached file metadata used in title details. This fills missing native languages, labels, forced and hearing-impaired flags without changing the AVPlay selection IDs. Matching uses subtitle order only when both complete lists have the same length and every known native language/Matroska codec anchor agrees; mismatches remain unknown. Matroska TrackNumbers are never used as AVPlay indices. Automatic tries the preferred external source immediately; when embedded fallback is needed, it waits for this bounded metadata check while video playback continues. A failed probe preserves native tracks and external fallback. Validate the correspondence on physical TVs, since firmware track filtering or reordering can differ. VOD selects them and forwards `onsubtitlechange` text cues to the shared overlay while silencing AVPlay's separate subtitle plane. Font size applies to that overlay. Embedded text cues use the same cleanup as external subtitles: HTML formatting and ASS styling markers are removed, line-break tags become real line breaks, and supported HTML entities are decoded. AVPlay callback durations are milliseconds supplied as strings on some firmware and numbers on others; the adapter normalizes both before scheduling cue removal. Embedded cue expiry follows the video playhead, so pauses and buffering do not consume the remaining cue duration; seeks and restart clear old text. Native timing adjustment is applied only by AVPlay, not a second time in the overlay. Timing adjustment uses `setSubtitlePosition` only when the firmware accepts it. Confirm cue delivery while silent and timing behavior on physical Tizen 3 and Tizen 6 TVs; synthetic SDK mocks cannot establish firmware behavior.

Browser playback selects text tracks exposed by the browser/player engine. The app's injected external WebVTT track is excluded from embedded discovery. A browser may decode MKV video while exposing none of its embedded subtitles. The metadata reader can still report their presence, but does not extract or render MKV cue data. In that case Automatic uses OpenSubtitles when configured. Full client-side MKV cue extraction remains a separate feasibility step: bounded indexed range access, provider CORS/range support, seek alignment and older-device performance must be established before adding it. No server extraction/proxy is introduced.

Metadata probes send provider credentials directly only to the provider. They do not use companion services, hosting, access services or subtitle relays. API credentials continue to go to their respective APIs. See [client credential policy](client-credential-policy.md).

## Verification

Synthetic tests cover Matroska metadata and bounds, direct credential destinations, failed/aborted probes, safe cache storage, language ranking, language-first source choice, failed selection, manual/Off locks, late downloads, native/external exclusivity, remembered choices, source-specific timing and title-detail unknown states. Browser and TV preview verification should exercise Automatic, another embedded track, Off, external replacement, resume and remote focus. Real provider movies are device acceptance examples, never automated fixtures.
